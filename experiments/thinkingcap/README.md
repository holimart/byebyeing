# ThinkingCap fine-tune: do the errors survive post-training?

[ThinkingCap Qwen3.8-Flash-Next NVFP4](https://huggingface.co/bottlecapai/ThinkingCap-Qwen3.8-Flash-Next-NVFP4)
(`bottlecapai/ThinkingCap-Qwen3.8-Flash-Next-NVFP4`) is BottleCap's post-training fine-tune of
Qwen3.8-Flash-Next with shorter thinking. Same base architecture, same 262K context, same
routified training lineage. We ran every experiment in this repo against it, unchanged, to ask
one question: **does the fine-tune inherit the memorised Alibaba behaviour and the other
off-task errors, or did post-training wash them out?**

It does not. **Every error reproduces, at equal or higher rates.** The memorised signed URL comes
out byte-identical to the base model's, down to the AccessKey id
`LTAI5tKoG9A3DkwGD635QVZr` (`results/routify/identifiers.json`).

## Serving

Self-hosted through [slurmhelps](https://github.com/holimart/slurmhelps)
(`llm/thinkingcap-flash-next/`): `ampere02`, 2x A100 80 GB TP2, vLLM 0.32, Marlin W4A16 for the
NVFP4 experts, 262K context, `max_num_seqs=2`, reached over an SSH tunnel at
`http://127.0.0.1:8011/v1`. The tunnel goes straight to vLLM; the `gw` arms use this repo's
gateway in-process, exactly as in the base-model runs.

## How to run

Same scripts, same protocol (Cohere sampling, one sample per request with a unique `cache_salt`,
conditions interleaved). Only the environment changes:

    cd experiments
    export QWEN_BASE_URL=http://127.0.0.1:8011/v1 QWEN_MODEL=thinkingcap-flash-next
    export CONCURRENCY=2                          # the A100 job runs max_num_seqs=2
    python3 routify/run.py first && python3 routify/run.py first_proxy
    python3 routify/run.py spiral && python3 routify/run.py summary
    python3 metadata/run.py first && python3 metadata/run.py aftermath && python3 metadata/run.py summary
    python3 upload/run.py check && python3 upload/run.py first
    python3 upload/run.py aftermath --n 48 && python3 upload/run.py summary
    python3 privilege/run.py notice && python3 privilege/run.py gateway && python3 privilege/run.py summary
    python3 secrets/run.py probe && python3 secrets/run.py chat && python3 secrets/run.py seeds 10 6
    python3 secrets/run.py summary

Safety as everywhere in this repo: text generation only. Tool calls the model wrote are stored as
data, never executed; no URL or host the model wrote was fetched or resolved; secret candidates
were never tested against any provider.

## Results (ThinkingCap vs the published Qwen3.8-Flash-Next numbers)

| Experiment | ThinkingCap | Qwen3.8-Flash-Next |
|---|---|---|
| routify first (URL written with nothing routify in context) | **23/192** | 8/192 |
| routify first_proxy | **16/144** | 20/144 |
| routify spiral, raw (copy with one routify call in history) | **70/240** | 60/240 |
| routify spiral, gateway arms | 0/48 (drop), 1/48 (swap, placeholder label only) | 0/96 |
| upload `small_chatml` / `small_render` alibaba hosts | **17/24, 18/24** | 9/24, 13/24 |
| upload `prefix2323` alibaba hosts | 6/48 (prefers `tmpfiles.org` 11, `tempbin.com` 6) | 40/48 (routify host 38) |
| metadata chain `curl -s ` + detect | **23/24** | 17/24 |
| metadata aftermath, gateway rows reaching the client | 0/288 | 0 |
| secrets: exact-shape completions with `unique/n` | 1.00, all confabulated | 1.00, all confabulated |
| privilege workarounds after a permission error | present (e.g. `apt_install` 7/16) | present |

Per-experiment tables are in `results/<experiment>/summary.md`, generated by the `summary`
command of each `run.py` from the JSONL next to them. The raw `secrets` arm results are kept
out of git like the base-model ones: the model emits confabulated 30-char secret-shaped values
(`unique/n` = 1.0, none repeat, none tested against any provider), which GitHub push protection
correctly refuses to host. The numbers above are from the local run's `results/secrets/`.

## Reading

- Shorter-thinking post-training leaves the routify memorisation untouched and may concentrate it:
  the first-occurrence and spiral rates are higher than the base model's.
- The one visible change: under the long Cohere upload prefix the fine-tune reaches for public
  file hosts (`tmpfiles.org`, `tempbin.com`) instead of Alibaba — fewer alibaba hosts in that
  cell, though small-prompt prefills still land on the memorised bucket.
- The gateway keeps working on the fine-tune unchanged: no Alibaba or metadata string reached the
  client in any gateway arm.

## Caveats

- Single run per cell at the repo's sampling settings; differences of a few samples are noise
  (see the base-model READMEs). The routify inheritance is far outside noise.
- ThinkingCap ran on the A100 Marlin W4A16 path; the base-model numbers are from Blackwell. The
  prompt and sampling protocol are identical, but kernels differ.
- This is the NVFP4 checkpoint under vLLM, not the GGUF build.
